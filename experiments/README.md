# Experiments

Finished runs that count for the report. One folder per run, holding only the small result
files (a few tens of KB). **Checkpoints never go in git.**

```
experiments/<run>/
  run_config.json        resolved config, git commit, GPU, schedule
  metrics.csv            per-epoch train loss + validation metrics
  eval_val_best.json     best.pth on val  (overall, per class, per event, per type, confusion matrix)
  eval_test_best.json    best.pth on test
```

## Adding a run

On the cluster the files are in `~/BRIGHT/results/<run>/`. On your laptop, from the repo root:

```bash
scp -r <user>@fep.grid.pub.ro:BRIGHT/results/<run> experiments/
python scripts/collect_results.py --write
```

Copy only those four files; delete `preds_*/` if you used `--save-preds`. Then commit
`experiments/<run>/` and this README together.

## Rules

1. **Naming:** `<model>_<variant>_s<seed>`, e.g. `unet_a_s42`. Never reuse a run name.
2. **Only full-recipe cluster runs** go here. Laptop runs (`--env local`) are smoke tests.
3. **Tied to a commit:** `run_config.json` must show a commit and `dirty: false`. A run trained
   from uncommitted code does not count.
4. **Three seeds** (42, 43, 44) per variant; the report uses mean ± std.
5. **Select on val, report test once.** Nothing is tuned by looking at test numbers.

## Checkpoints

`checkpoints/<run>/best.pth` (~370 MB with optimizer state) stays on the cluster, in the
home folder of whoever trained the run, listed below. Share it only when someone needs it.
Delete `last.pth` once a run has finished; it is only needed to resume.
